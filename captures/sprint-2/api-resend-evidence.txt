       -X POST http://localhost:3001/api/contact \
       -H "Content-Type: application/json" \
       -d '{"typologie":"locaux-commerciaux","transaction":"location",
            "surfaceMin":80,"surfaceMax":200,
            "budgetMin":3000,"budgetMax":8000,
            "deadline":"court-terme","financement":"pret-en-cours",
            "secteur":"restauration","zones":["paris-1"],
            "nom":"Test Resend","email":"test-resend-401@example.com",
            "telephone":"06 12 34 56 89","consentement":true}'

Réponse HTTP côté client :
  [HTTP_STATUS=502]
  {"error":"Envoi impossible pour le moment, réessayez ou appelez-nous."}

Log serveur Next.js (`pnpm dev`) :
  [contact] internal send failed API key is invalid
  POST /api/contact 502 in 331ms

Interprétation
============================================================
- Le pipeline complet a fonctionné : Zod a validé le payload (200 sortie
  validation), le rate-limit n'a pas bloqué, l'appel à Resend a bien été
  émis, et Resend a répondu "API key is invalid" (équivalent du 401
  attendu par le brief §289).
- L'endpoint masque le 401 de Resend en 502 côté client pour ne pas
  exposer l'auth du service tiers (cf. `lib/email.ts` → `send()` catch
  qui retourne `{ ok:false, error }` consommé par `route.ts`).
- L'auth est le SEUL blocage : la mécanique (Zod + rate-limit + Resend
  SDK + templates HTML + try/catch séparé internal/user) fonctionne de
  bout en bout.
